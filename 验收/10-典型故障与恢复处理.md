# 典型故障与恢复处理

## 要证明的规则

下面每一行都留有记录，并且不把已经提交的任务抹掉。

- 受理响应丢失后，原幂等键取回原任务。
- Kafka 已收下、Outbox 未标记时，用原消息 ID 再投，不回退任务状态。
- 接管已提交、offset 未提交时，重投认得出原来的代次。
- offset 已提交、图还没启动时，租约到期后发出恢复消息。
- 旧执行者回来不能回写。
- 动作编号已经记下、假写还没发出时，重试沿用原号。
- 假写已成功、结果还没写回时，不把假写再做一遍。
- Checkpoint 已提交、结果确认未提交时，从已登记的恢复点继续，不用图位置证明写已经完成。
- 旧代次事后写的存档不能登记成当前恢复点。
- 取消请求先到时，后到的完成提交要重新看当前状态。
- 事件已提交、连接中断后，按游标补读。补读期间的新事件留到下一轮。
- 游标超出保留期时要求重新同步。
- 外部结果无法再核实就转人工，不自动重试。
