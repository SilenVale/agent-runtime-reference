# 技术版本与验收要求

## 要证明的规则

- 投递器在受理提交之后退出，原消息仍可再投。
- 接管后、确认前退出，不留下新代次，消息可以再被接管。
- 确认之后、图启动之前退出，还没有 Checkpoint，之后靠租约恢复。
- 消费组再均衡从已提交位移继续，不把位移拨回零。
- 恢复消息重复不再接管。旧轮次迟到被忽略，不推高代次。
- 多个扫描实例重叠时不重复登记。
- 旧 Worker 不能续上自己的租约或回写结果。
- 第一个 Checkpoint 还没生成时，按输入或操作账本定位。
- SSE 断线后按游标补读。
- 只有当前执行者能提交结果。同一个 operation_id 不让假写写第二次。
- 没确认的消息仍有待发送记录。到期租约会登记下一次调度。
- Worker 槽位为 0 时，恢复扫描仍能登记 Outbox。扫描跟 Runtime 进程在一起。
- 扫描主实例退出、另一实例接上时，已有次数不清零，短时重叠不重复登记。
- 结果不明的写不直接重做。

本仓库用 Java 实现接入层、消息投递和 Runtime。PostgreSQL、Kafka、MySQL 的职责仍按架构文档。不把 FastAPI 或 aiokafka 装进来冒充 PDF 里的 Python 基线。
